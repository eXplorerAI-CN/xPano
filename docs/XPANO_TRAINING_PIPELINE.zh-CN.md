# xPano 当前训练管线说明

本文说明当前 xPano 从收到素材到产出高斯模型的完整处理流程。这里的“训练管线”不只指最后的高斯训练，还包括训练前必须完成的素材准备、相机对齐、训练数据导出和点云选择。

## 一句话说明

xPano 先把不同来源的素材整理成统一的图像和相机数据，再用 Metashape 或 COLMAP 求出每张图像的拍摄位置，最后把图像、相机参数和选定点云交给 LichtFeld Studio（LFS）训练高斯模型。

```text
导入素材
   ↓
抽帧、调色和整理照片
   ↓
相机对齐并生成基础点云
   ↓
导出标准 COLMAP 训练数据
   ↓
选择标准点云或致密点云
   ↓
LichtFeld Studio 高斯训练
   ↓
得到 PLY / SOG / SPZ 高斯模型
```

每个阶段都会先检查上一个阶段的产物。缺素材、缺相机模型、缺点云、环境不可用或输出目录不可写时，xPano 会停在当前阶段并说明原因，不会带着不完整数据继续训练。

## 1. 素材进入 xPano 后如何分类

xPano 目前把素材分成四类。分类决定了抽帧方式、相机模型和后续对齐流程。

| 用户导入的内容 | xPano 中的类型 | 实际处理方式 |
|---|---|---|
| DJI Osmo 360 的 `.osv`、Insta360 的 `.insv` | 全景视频 | 按设定频率抽取左右鱼眼画面；对齐时保留双鱼眼结构 |
| `.mp4`、`.mov`、`.avi`、`.mkv`、`.m4v`、`.webm` | 普通视频 | 抽成一张张普通透视照片，并按普通相机处理 |
| 照片文件或照片文件夹 | 普通照片 | 扫描照片、建立缩略图，并按 EXIF 和图像尺寸识别相机/镜头 |
| 无人机照片文件或文件夹 | 航拍照片 | 处理方式与普通照片相近，但在工程中保留航拍素材身份 |

不支持的文件不会进入后续管线。导入只是把素材登记到 xPano 工程中，真正的抽帧、调色和整理发生在“素材准备”阶段。

### 全景视频

- 用户设置抽帧频率、起止时间和最多抽取多少帧。
- `.osv` 按双视频流抽出左右鱼眼图；成对的 `.insv` 会识别左右文件并配对。
- 抽帧优先尝试 CUDA 硬件解码，Windows 下其次尝试 D3D11VA；硬件解码不可用时自动回退到 CPU 解码。
- 硬件解码失败只会回退解码方式，不会改变抽出的图像内容和后续相机模型。
- 全景视频在对齐阶段仍使用原始左右鱼眼图，不会先切成立方体图再对齐。

### 普通视频

- 用户同样可以设置抽帧频率、起止时间和帧数上限。
- 每个时间点只产生一张普通透视图。
- 用户可指定“广角”或“标准”初始视角，xPano 用它给没有可靠相机信息的视频帧设置合理的初始焦距。
- 普通视频不会被套用全景鱼眼模型，也不会进入全景 Station 分组。

### 普通照片和航拍照片

- xPano 扫描文件夹中的有效图片，并为图片建立索引和缩略图。
- 默认不限制处理张数；如果用户设置了数量上限，xPano 会在整组照片中均匀取样，而不是只拿文件夹开头的照片。
- xPano 根据图像尺寸、相机品牌/型号、镜头信息、焦距等 EXIF 数据拆分传感器，避免把不同相机或不同镜头错误地绑成同一套内参。
- 照片始终按普通 Frame 相机处理，不会因为和全景素材放在一起而变成鱼眼相机。
- 没有套 LUT 时，xPano 尽量用硬链接或复制方式整理照片，不重复压缩原图；需要套风格 LUT 时才会生成调色后的训练副本。

## 2. LUT 在哪个阶段生效

LUT 在素材准备阶段生效，进入对齐和训练的已经是处理后的图像。

- 还原 LUT 用于把 Log 素材恢复到正常显示色彩。
- 风格 LUT 用于统一最终画面风格。
- 两者同时开启时，顺序固定为“先还原，后风格”。
- DJI `.osv` 可使用 xPano 内置的 Osmo 360 D-Log M 转 Rec.709 LUT。
- Insta360 `.insv` 当前只支持用户手动选择 LUT，不会自动套用 DJI LUT。
- 普通视频、普通照片和航拍照片也可以只套风格 LUT。
- LUT 必须是有效的 `.cube` 文件；xPano 会先让 FFmpeg 验证 LUT，验证失败则停止该素材的准备工作。

LUT 会改变训练图像的颜色，因此它不是单纯的预览滤镜。更换 LUT 后应重新准备素材、重新导出训练图像，再开始新的训练。

## 3. 素材准备完成的判定

每条素材轨道准备完成后，xPano 会记录：

- 实际抽出的帧或扫描到的照片；
- 每张图像的缩略图和是否参与对齐；
- 全景帧的左右鱼眼对应关系；
- 普通照片的相机/镜头分组；
- 本次使用的裁剪、抽帧和 LUT 设置；
- 一份统一的素材清单。

新生成的帧和照片默认参与对齐。用户在素材页取消选择的项目不会写进本次对齐清单。

只有被选中的素材轨道处于“已就绪”状态，而且至少还留有一张可用图像时，才能开始对齐。素材参数变化、源文件变化或重新选择图片后，旧的对齐结果会被视为过期，需要重新处理相应阶段。

## 4. xPano 如何对齐素材

### 默认推荐：Metashape

Metashape 是当前同时支持全景视频、普通视频、普通照片和航拍照片的完整路径。

#### 只有全景素材时

1. 每个抽帧时刻建立一个 Station，里面放左右两张鱼眼图。
2. 左右画面使用独立的等距鱼眼传感器，并套用 xPano 已验证的初始标定。
3. Metashape 提取和匹配特征点，然后求解全景相机骨架。
4. 骨架求解后，把 Station 组恢复为普通 Folder，再做保守的外参优化。

这里的 Station 是在告诉 Metashape：同一时刻的左右镜头属于同一个拍摄位置。对齐完成后释放为 Folder，是为了让相机外参继续做小范围优化，而不是把两只镜头永远锁死。

#### 全景素材加普通视频或照片时

xPano 不会把所有图像一次性混在一起乱求解，而是分两步：

1. 先只用全景左右鱼眼建立稳定的全景骨架。
2. 再导入普通视频帧、普通照片和航拍照片。
3. 保留全景阶段已经找到的特征点，把普通相机增量接入现有骨架。
4. 最后对所有已接入相机做一次保守的全局优化。

这样做的目的，是避免数量很多、视角差异很大的普通照片在一开始就破坏全景双镜头的基本结构。

#### 只有普通视频或照片时

全景专用阶段会自动跳过，所有图像都按普通 Frame 相机进入 Metashape，再执行匹配、对齐和优化。

### 可选：COLMAP

当前 COLMAP 路径只开放给纯全景素材。它会准备全景图像、提取 SIFT 特征、匹配、增量重建，再选择最佳模型。

只要工程中包含普通视频帧、普通照片或航拍照片，xPano 就会拒绝使用 COLMAP 对齐，提示改用 Metashape。这个限制是主动保护：当前版本没有把混合相机的 COLMAP 回归测试做完整，因此不会冒险生成可能错误的训练数据。

## 5. 部分相机没对上时怎么处理

xPano 不要求达到某个固定对齐率才算成功，也不会因为少量相机没对上就把整项任务判死。

当前规则是：

- 至少要存在一个包含已对齐相机的有效结果；
- 会记录总相机数、已对齐数、未对齐数和对齐率；
- 未对齐相机不会进入最终训练数据；
- 对齐质量不理想时会给出警告，用户可以打开保存的 `work/xpano.psx` 在 Metashape 中手动修正。

如果 Metashape 产生多个 Component，xPano 不会把它们混合导出。默认选择“已对齐相机最多”的 Component；数量相同时，再参考连接点数量。成果页可以重新读取 PSX 中的 Component，选择合适的一个重新导出。

这意味着：主体结构正确但少量照片没对上，仍可继续；如果相机被分成多个互不相连的大块，则应先确认主 Component，必要时手动修正 PSX。

## 6. 对齐完成后导出什么

无论对齐使用 Metashape 还是 COLMAP，xPano 最终都会整理成 LFS 能读取的标准 COLMAP 数据集：

```text
工程目录/
├─ images/                 训练图像
└─ sparse/0/
   ├─ cameras.bin          相机内参
   ├─ images.bin           每张图像的位姿
   └─ points3D.bin         当前使用的点云
```

导出时：

- 已对齐的全景鱼眼相机会转换成多张普通透视立方体图；
- 普通视频帧、普通照片和航拍照片会导出为去畸变后的普通透视图；
- 所有图像和点云写入同一个、坐标一致的 COLMAP 模型；
- xPano 会检查训练图像、相机记录、图像位姿和点云文件是否齐全。

需要特别区分：全景素材是“用原始双鱼眼完成对齐，之后才切成立方体图用于训练”。如果拿切好的立方体图反过来做初始对齐，相机约束会变弱，也更容易出现错误匹配。

## 7. 标准点云、致密点云与训练的关系

对齐成功后，xPano 会把稀疏重建点云登记为“标准点云”，并默认选中它。因此不做致密化也可以直接训练。

致密化是可选增强：

- 致密化成功后会新增一个点云版本，不覆盖标准点云；
- 用户可以在成果页选择标准点云或某个致密点云作为当前训练输入；
- 切换点云时，xPano 会把该版本安全地写入当前 COLMAP `points3D.bin`；
- 只有状态为“已就绪”的当前点云才能训练；
- 新一轮对齐会生成新的标准点云，并把旧的致密点云标为过期，防止跨重建误用。

所以，单独把一个 `.ply` 放进工程目录并不等于训练数据已经就绪。LFS 训练需要的是“图像 + 相机内参 + 相机位姿 + 当前点云”这一整套 COLMAP 数据。

## 8. 什么条件下允许开始高斯训练

xPano 会同时检查以下条件：

1. 已打开有效的 xPano 工程。
2. 当前没有其他素材、对齐或训练任务占用执行管线。
3. 内置 LichtFeld Studio 可以启动。
4. NVIDIA CUDA 运行环境可用。
5. Vulkan 图形运行环境可用。
6. 工程中存在 `images/` 和完整的 `sparse/0` 模型。
7. 对齐状态为完成或结果仍可用，且当前选中的点云版本状态为“已就绪”。
8. 训练输出目录可以创建和写入。

任何一项不满足，“开始训练”都会被阻止，并引导用户去素材页、对齐页、成果页或重新检查环境。

如果批量队列正在运行，手动模式不能同时启动训练；已经排队或正在执行的批量任务也不能在详情页临时修改参数，避免任务执行到一半输入发生变化。

## 9. LFS 实际如何开始训练

通过检查后，xPano 会为这次训练创建独立目录：

```text
work/training/runs/<本次任务 ID>/
```

随后按以下顺序执行：

1. 使用随 xPano 打包的 LFS 和隔离运行配置启动 LichtFeld Studio。
2. 默认拉起 LFS 原生 GUI，让用户能看到真实训练窗口。
3. LFS 加载完 COLMAP 数据集后，xPano 再通过 LFS 的本地接口写入最终训练参数。
4. 参数确认完成后，由 xPano 调用 LFS 的正式训练入口开始训练。

之所以在数据加载后再次写入参数，是因为 LFS v0.5.3 会对大于 300 张图像的数据集自动缩放训练计划。xPano 的二次确认可以保证实际迭代步数就是用户设置的步数，而不是被 LFS 悄悄放大。

### 当前默认训练参数

| 参数 | 默认值 | 人话解释 |
|---|---:|---|
| 迭代步数 | 30,000 | 标准训练时长 |
| 优化策略 | MRNF | 当前推荐的通用策略 |
| SH 阶数 | 3 | 保留较完整的视角相关颜色表现 |
| 最大高斯数 | 1,000,000 | 控制模型规模和显存占用 |
| 图像缩放 | 自动 | 由 LFS 和最大宽度共同控制 |
| 最大图像宽度 | 3,840 px | 控制显存、速度和可保留细节 |
| CPU 图像缓存 | 开启 | 减少重复读取和解码 |
| 文件系统缓存 | 开启 | 利用磁盘缓存提高长任务稳定性 |
| 双边网格 | 开启 | 默认启用的外观优化选项 |
| Mip 抗锯齿 | 关闭 | 需要时手动开启 |
| 训练评估 | 关闭 | 默认不额外划分评估流程 |
| GUI | 开启 | 默认显示 LFS 原生窗口 |

xPano 还提供快速、标准和高质量预设：

- 快速：1 万步、最多 50 万高斯、图像缩小到 1/2、最大宽度 2560。
- 标准：3 万步、最多 100 万高斯、自动缩放、最大宽度 3840。
- 高质量：6 万步、最多 200 万高斯、原始比例、不限制最大宽度。

高质量并不保证一定更好。图像更多、分辨率更高、高斯上限更大时，训练时间、显存和内存占用都会明显上升。显存不足时，优先降低最大图像宽度或使用 1/2 缩放，比盲目减少相机数量更稳妥。

## 10. 训练进度是怎么拿到的

xPano 每秒从 LFS 读取一次真实训练状态，包括：

- 当前迭代步数和总步数；
- 当前 Loss；
- 当前高斯数量；
- 暂停或运行状态；
- 根据实际迭代速度估算的剩余时间。

同时，xPano 增量读取 LFS 日志，用于识别数据集加载、检查点保存、训练成功和致命错误。进度接口偶尔读取失败只会显示警告，不会立即杀掉一个仍在正常训练的 LFS；此时日志仍作为后备状态来源。

## 11. 怎样才算真正训练成功

训练完成必须同时满足两个条件：

1. LFS 明确报告训练成功；
2. 本次输出目录中实际存在可交付的 `.ply`、`.sog` 或 `.spz` 高斯模型。

只有检查点而没有最终模型，不算完成。LFS 报告成功但 5 秒内没有找到模型文件，也会被判为失败，避免界面显示完成而结果目录为空。

成功后，xPano 会记录实际模型路径，并把工程训练状态改为“完成”。每次重新训练使用新的任务目录，不会直接覆盖上一轮结果。

常见终止情况：

- 用户正常取消：当前训练被终止，工程记录为中断；
- 用户在训练完成前手动关闭 LFS：视为 LFS 提前退出，任务失败；
- CUDA 显存不足：记录为 GPU 内存不足；
- CUDA、Vulkan 或 DLL 加载失败：记录对应运行环境错误；
- LFS 长时间没有完成启动和数据加载：由启动看门狗判定为启动卡死；
- 训练失败时会在本次输出目录写入诊断信息，保留近期日志和本次参数，便于排查。

## 12. 批量模式如何串行执行

批量任务仍然调用上述同一套素材、对齐和训练管线，不存在另一套“简化版”处理逻辑。

批量阶段只能按前缀开启：

- 只做素材准备；
- 素材准备 + 对齐；
- 素材准备 + 对齐 + 训练。

不能跳过素材准备直接对齐，也不能跳过对齐直接训练。保存任务时，xPano 会把素材选择和各阶段参数写入工程，并冻结当时的工程版本；工程后来被其他操作修改时，旧任务不会悄悄套用新数据，而是报告版本冲突。

队列运行时：

1. 一次只执行一个项目。
2. 当前项目按素材、对齐、训练顺序运行。
3. 任一阶段失败，当前项目立即标记失败，不再执行它的后续阶段。
4. 失败不会终止整个队列，xPano 会继续下一个排队项目。
5. 软件关闭时，正在执行的项目标记为中断，尚未开始的项目继续保留在队列中。

任务详情页显示的阶段、进度、已用时间和日志来自实际后台任务，不是前端模拟进度。

## 13. 哪些变化需要重跑哪些阶段

| 用户做的修改 | 至少需要重跑 |
|---|---|
| 修改抽帧频率、起止时间或帧数上限 | 素材准备 → 对齐 → 训练 |
| 增删素材，或改变参与对齐的图片 | 素材准备/清单 → 对齐 → 训练 |
| 更换还原 LUT 或风格 LUT | 素材准备 → 对齐 → 训练 |
| 修改相机类型或普通视频初始视角 | 素材准备 → 对齐 → 训练 |
| 在 Metashape 中手动修正相机或选择其他 Component | 从 PSX 重新导出 → 重新训练 |
| 仅切换标准点云/已存在的致密点云 | 重新训练 |
| 仅调整地面方向或世界坐标 | 应用变换后重新训练 |
| 只修改迭代数、高斯上限、分辨率等训练参数 | 只需重新训练 |

## 14. 实际使用时最重要的判断

- 预览正常不代表已经可以训练；预览只说明素材能读，训练还需要完整对齐和 COLMAP 数据。
- 对齐率不是唯一标准。主体 Component 正确、相机结构没有大范围错位时，少量相机未对齐可以接受。
- 多 Component 不能混着导出。应选择相机最多、结构正确的主 Component；如果主结果本身错误，应先在 Metashape 中修正。
- 致密化不是训练的硬性前置条件。标准稀疏点云可直接训练，致密点云只是可选输入版本。
- LFS GUI 被手动关闭不等于“让 xPano 在后台继续”；当前实现会把它视为训练进程提前退出。
- 最终成功以真实高斯模型文件为准，不以进度条到 100% 或存在检查点为准。
