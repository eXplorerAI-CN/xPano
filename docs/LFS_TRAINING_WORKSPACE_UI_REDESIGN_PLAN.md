# LichtFeld 高斯训练工作区 UI 重构方案

状态：设计完成，等待确认后实施

范围：只重构 xPano 内的训练工作区 UI、交互层级和前端状态表达；不修改 LichtFeld 训练算法、参数协议、任务生命周期或发布内容。

## 1. 设计结论

推荐将当前固定的“参数面板 + 监控面板”改为**状态自适应的单一任务工作区**：

- 空闲时以训练配置和开始操作为主，不显示空进度、空指标和空终端。
- 训练时以真实进度和关键指标为主，已提交参数只读展示。
- 完成时以产物和后续操作为主，不继续保留占满页面的监控终端。
- 失败或中断时显示短错误和恢复操作，原始日志在“运行详情”中展开。

这比重新美化现有 50/50 两栏更简单，也更符合用户在每个状态下真正要完成的任务。

## 2. 当前问题

| 当前表现 | 用户影响 | 重构原则 |
|---|---|---|
| 两个同权重的大面板 | 不知道先看哪里，页面像开发仪表盘 | 每个状态只保留一个视觉中心 |
| 外层面板中继续嵌套大量卡片 | 分区碎、边框多、层级扁平 | 分组使用标题、留白和分隔线 |
| 空闲时展示 0%、四个空指标和空日志 | 首屏信息大多无效 | 空闲态只显示设置、就绪状态和主操作 |
| 运行时参数仍可编辑 | 容易误以为会影响当前训练 | 当前任务参数只读，下一次训练再修改 |
| 8-10px 标签和英文眉题 | 阅读困难，产品语言不统一 | 最小辅助字号 11px，默认全部中文 |
| 显示版本、运行时路径、数据集路径和实现说明 | 开发信息挤占主流程 | 技术细节进入帮助层或运行详情 |
| 主按钮远离参数且禁用原因不可见 | 不知道为何不能开始 | 启动摘要与按钮固定在同一区域 |
| 本地 preset 状态与真实参数可能不一致 | 高亮方案可能误导 | 从配置反推预设，无法匹配时显示“自定义” |

## 3. 推荐布局

### 3.1 空闲 / 可配置

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 高斯训练                                      训练数据已就绪  ✓      │
├──────────────────────────────────────────────┬──────────────────────┤
│ 训练方案                                     │ 本次训练             │
│ [快速预览] [标准] [高质量] [自定义]          │ 标准 · 30,000 步      │
│                                              │ 自动 3840px · MRNF    │
│ 质量与规模                                   │ 双边网格已开启        │
│ 迭代次数        最大高斯数量                 │                      │
│ 图像分辨率      优化策略                     │ 输入状态              │
│ SH 阶数                                      │ 数据集            ✓  │
│                                              │ 训练点云          ✓  │
│ 高级设置                              [展开] │ LichtFeld         ✓  │
│ ──────────────────────────────────────────── │                      │
│                                              │ [      开始训练     ] │
│                                              │ 禁用时显示明确原因   │
└──────────────────────────────────────────────┴──────────────────────┘
```

- 左侧是唯一可滚动的配置区。
- 右侧是 280-304px 的固定启动摘要，不再拆成多个状态卡片。
- “训练方案”使用分段控件，不使用三张选择卡。
- 高级设置是同一表单内的折叠分组，不再套一层卡片。
- 页面主按钮统一为“开始训练”，不在按钮中重复第三方实现名称。

### 3.2 训练中

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 正在训练                                  12,480 / 30,000 · 41.6%   │
│ ████████████████████────────────────────────────── 预计剩余 18:24   │
├───────────────────────────────────────────────────┬─────────────────┤
│ Loss             高斯数量          已运行时间     │ 本次配置        │
│ 0.031284          824,512           00:36:18       │ 标准 / MRNF     │
│                                                   │ 3840px / SH 3   │
│ 当前状态                                          │ 双边网格开启    │
│ 正在优化高斯参数 · 训练窗口已打开                 │                 │
│                                                   │ [   停止训练  ] │
├───────────────────────────────────────────────────┴─────────────────┤
│ 运行详情（最近 120 条）                                      [展开] │
└─────────────────────────────────────────────────────────────────────┘
```

- 进度条使用单一品牌色，不使用渐变。
- 三项关键指标用分隔线组织，不再各自放入卡片。
- 配置摘要只读；不允许视觉上修改正在运行的参数。
- “停止训练”使用危险操作样式并要求确认。
- 原始日志默认折叠。用户主动展开后才显示固定高度终端，并保留滚动位置。

### 3.3 完成

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 训练完成  ✓                                                        │
│ 已生成高斯模型                                                      │
├─────────────────────────────────────────────────────────────────────┤
│ 30,000 次迭代        最终 Loss        1,012,486 个高斯              │
│                                                                     │
│ 训练结果                                                            │
│ xpano_gaussian.ply                         [打开结果目录] [再次训练] │
├─────────────────────────────────────────────────────────────────────┤
│ 运行详情                                                      [展开] │
└─────────────────────────────────────────────────────────────────────┘
```

- 默认只显示产物文件名，不显示工程内部相对路径。
- “打开结果目录”复用现有 `open_output_folder` 命令。
- “再次训练”返回设置态并保留上一次配置。
- 当前后端没有训练结果内嵌预览契约，本轮不虚构“预览模型”按钮。

### 3.4 未就绪、失败与中断

| 状态 | 主内容 | 主操作 | 运行详情 |
|---|---|---|---|
| 未打开工程 | 尚无可训练工程 | 前往素材与处理 | 隐藏 |
| 数据集缺失 | 需要先完成对齐和训练数据导出 | 前往对齐与重建 | 隐藏 |
| 点云缺失 | 需要选择有效训练点云 | 前往成果与后处理 | 隐藏 |
| 运行时缺失 | LichtFeld 环境不可用 | 重新检查 | 默认折叠 |
| 失败 | 显示经过整理的一句话错误 | 返回设置 / 重试 | 默认展开 |
| 已中断 | 显示已保存的当前状态 | 返回设置 / 重新开始 | 默认折叠 |

禁用按钮旁必须显示一条具体原因，不能只通过降低透明度表达。

## 4. 信息层级

### 默认可见

- 当前训练状态。
- 训练方案和常用参数。
- 简洁的输入就绪状态。
- 当前任务真实进度、迭代、Loss、高斯数量和 ETA。
- 完成后的产物名称和可执行操作。

### 按需显示

- 参数含义、推荐值和性能取舍：复用现有 `ParameterHelp` 弹层。
- 高级参数：单个折叠分组。
- 原始任务日志、运行时路径、数据集路径、LichtFeld 版本和命令诊断：运行详情。

### 从默认界面删除

- `GAUSSIAN TRAINING`、`TRAINING MONITOR`、`idle` 等英文状态文本。
- “xPano 负责参数、进度和产物归档”等实现职责说明。
- 未发生训练时的 0% 仪表盘、空指标和空终端。
- 原始运行时路径和数据集路径。
- “启动后自动创建训练目录”等开发行为描述。

## 5. 参数组织

### 常用设置

- 训练方案：快速预览 / 标准 / 高质量 / 自定义。
- 迭代次数。
- 最大高斯数量。
- 图像分辨率。
- 优化策略。
- SH 阶数。

“图像缩放”和“最大宽度”在默认 UI 中合并为一个分辨率控件：

- 自动（最大 3840px）
- 原始分辨率
- 1/2
- 1/4
- 自定义上限

底层仍写回现有 `resizeFactor` 和 `maxWidth`，不改变训练参数协议。

### 高级设置

- 性能：CPU 图像缓存、文件系统缓存。
- 质量：双边网格、Mip 抗锯齿、训练评估。
- 输入处理：数据居中、在线去畸变。
- 背景：背景模式、颜色。
- 验证：测试集间隔。

开关右侧不再常驻解释句。非显然参数使用 `?` 帮助层展示“作用 / 推荐 / 代价”。双边网格继续默认开启。

## 6. 视觉系统

- 颜色：完全复用 xPano 的 brand、data、success、warning、danger 和 surface token。
- 页面背景：保持 AppShell 现有背景，不增加 LFS 专属渐变或装饰图形。
- 字号：页面标题 16-18px；区标题 13px；正文/控件 12px；辅助文本最小 11px；关键进度 24-28px。
- 间距：4 / 8 / 12 / 16 / 24px。
- 圆角：控件 6px，一级面板不超过 8px。
- 分区：优先留白、标题和 1px 分隔线；卡片只保留给真正重复的结果项，本页面默认不需要卡片网格。
- 图标：继续使用 Lucide；图标只表示状态或操作，不作装饰。
- 动效：复用 140ms / 260ms token；仅状态切换、折叠和进度更新产生动效，不持续闪烁。

## 7. 响应式规则

- `>= 1180px`：主设置区 + 304px 启动摘要。
- `1024-1179px`：主设置区 + 264px 摘要；字段仍保持两列，缩短辅助文本。
- 高度不足 780px：标题区压缩，只有主设置区滚动；右侧按钮始终可见。
- 不允许整页滚动后才能访问“开始训练”或“停止训练”。
- 未来若取消应用的 1024px 最小宽度，低于 960px 时改为单列，并将主操作固定在工作区底部；本轮不为不存在的窗口规格增加复杂布局。

## 8. 前端结构

保持一个编排组件，拆出五个有真实职责的视图，不建立通用卡片框架：

```text
TrainingWorkspace
├─ TrainingReadinessNotice
├─ TrainingSetupView
│  ├─ TrainingPresetControl
│  ├─ TrainingBasicFields
│  └─ TrainingAdvancedFields
├─ TrainingRunView
├─ TrainingResultView
└─ TrainingDiagnosticsDrawer
```

新增两个纯函数：

- `deriveTrainingPreset(config)`：返回 fast / balanced / quality / custom。
- `trainingBlockReason(readiness, running, project)`：统一生成按钮禁用原因和恢复入口。

`TrainingWorkspace` 只根据持久化工程状态和实时任务状态选择视图；不引入第二套任务状态。

## 9. 实施顺序

1. 先为视图状态、预设反推、禁用原因和进度展示补纯逻辑测试。
2. 建立状态自适应工作区骨架，删除固定 50/50 外层面板和空闲监控。
3. 将预设改为分段控件，重排常用参数并实现“自定义”状态。
4. 重组高级参数，接入现有参数帮助层，移除常驻开发解释。
5. 实现运行、完成、失败和中断视图，锁定已提交配置。
6. 将日志改为运行详情抽屉，失败时默认展开。
7. 接入现有结果目录打开命令和停止确认。
8. 完成浅色/深色与 1024x720、1280x800、1920x1080 的视觉验收。

## 10. 验收标准

- 空闲首屏不出现 0% 空仪表盘或空终端。
- 页面默认不出现 LFS 版本、原始路径、内部职责说明、英文状态值。
- 1024x720 下主操作始终可见，常用设置不被横向压坏。
- 页面最多两个一级区域，不出现卡片套卡片。
- 常用控件正文不低于 12px，辅助文本不低于 11px。
- 任意时刻只有一个主按钮。
- 禁用开始训练时必须显示明确原因和可执行恢复入口。
- 训练中参数不可编辑，并显示实际提交配置。
- 预设高亮与配置一致；任何手动偏离都显示“自定义”。
- running / complete / failed / interrupted / stale / missing-input 状态均有独立可恢复界面。
- 日志折叠后不抢占主区；展开后保持用户滚动位置且不闪烁。
- 浅色、深色下文本、边界、状态色和焦点状态均可读。
- 不新增前端依赖，不修改训练参数和后端任务协议。

## 11. 未采用的方向

### 保留现有两栏，仅调整比例

改动最小，但空闲时仍会展示无意义监控，训练中仍会保留可编辑设置，不能解决根本问题。

### 使用“设置 / 运行 / 结果”手动标签页

层级清楚，但允许用户进入与任务状态不一致的页面，还会与底部工作区导航形成第二套导航。状态自适应视图更直接。

### 做成分步向导

首次使用容易理解，但重复训练需要频繁前进后退，并且参数本身不足以支撑多步流程。对专业桌面工具来说过度设计。
